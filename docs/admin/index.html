防呆機制怎麼運作

獨立監測

每週更新負責抓取、產製與發布；另一支獨立看門狗核對結果，發現落後時只觸發既有更新流程。兩者分開運作，避免更新工作自己顯示成功，網站卻沒有真的更新。

  1. 01 偵測新一期

    週五至週六檢查上游期數與來源版本。沒有變動就安全結束，有新期或來源異動才開始產製。

  2. 02 發布前擋錯

    一般錯誤單篇最多嘗試 3 次；10 篇以內可隔離後繼續，第 11 篇起視為系統性故障並停止內容發布。安全攔截則直接隔離，不反覆送出。

  3. 03 每日獨立核對

    每天 12:47 比對上游、GitHub 主資料、全文覆蓋率與公開網站，不只檢查排程有沒有顯示成功。

  4. 04 異常就診斷補跑

    看門狗發現落後時會避免重複工作並自動補跑；失敗分類與人工處理建議直接寫入下方維運紀錄。

上游已有新期，GitHub 還是舊期重新執行「Weekly Economist update」
GitHub 已更新，公開網站仍是舊版重新執行 GitHub Pages 發布
金鑰、額度或連線異常依下方「此次維運診斷」調整 Azure 或 GitHub Secrets

安全邊界：看門狗可觸發既有更新流程，但不能自行修改金鑰、提高 Azure 額度或關閉內容安全篩選。遇到這些情況會保留舊站，並把需要人工調整的項目寫在維運診斷。
