防呆機制怎麼運作

唯讀監測

每週更新負責抓取、產製與發布；另一支獨立看門狗只負責核對結果。兩者分開運作，避免更新工作自己顯示成功，網站卻沒有真的更新。

  1. 01 偵測新一期

    週五至週六檢查上游期數與來源版本。沒有變動就安全結束，有新期或來源異動才開始產製。

  2. 02 發布前擋錯

    文章、導讀、標籤與中英文全文通過完整性稽核才會提交。任何一步失敗，都保留原本可用的網站。

  3. 03 每日獨立核對

    每天 12:47 比對上游、GitHub 主資料、全文覆蓋率與公開網站，不只檢查排程有沒有顯示成功。

  4. 04 異常就亮紅燈

    只要期數、版本或全文數量不一致，看門狗就會失敗，並在上方「來源同步」或「網站發布」顯示異常。

GitHub 已更新，公開網站仍是舊版重新執行 GitHub Pages 發布
中文全文少於文章總數查看週更工作中的翻譯與全文稽核步驟

目前權限邊界：看門狗只讀取並比對資料，不會自動改資料、補跑模型或重新發布。這可避免誤觸大量 API 用量或覆蓋正確網站；確認異常後，再依上方對應方式處理。
