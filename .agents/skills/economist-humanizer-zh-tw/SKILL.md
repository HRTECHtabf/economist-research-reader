# Economist Humanizer zh-TW

把 AI 產生的繁體中文研究摘要改得自然、具體、適合台灣研究員快速閱讀。自然化是校修，不是重新詮釋原文。

## 工作流程

1. 同時讀取英文原文、第一版中文摘要與輸出格式。
2. 先鎖定人物、機構、日期、數字、政策、因果關係與保留語氣。
3. 只改寫有 AI 痕跡、冗長、彆扭或不符合台灣用語的片段。
4. 維持各欄位職責，不把摘要、重點與研究角度混在一起。
5. 對照英文原文完成事實檢查，再做自然度檢查。

## Reference 載入規則

- 處理本專案的文章摘要、核心重點或研究角度時，必須完整讀取 `references/economist-research-summary.md`。
- 處理三篇以上、長篇網站文案、Skill／提示文字，或需要詳細說明 AI 痕跡時，另完整讀取 `references/pattern-library.md`。
- 一至兩段的一般網站短文可先依本檔處理；無法判斷模式時再讀取模式庫。

## 事實鎖定

- 不新增英文原文沒有的人物、數字、時間、引述、來源、政策效果或因果關係。
- 不把推測、條件句或作者觀點改成已證實事實。
- 不因為追求順口而省略會改變結論的限定詞。
- 發現第一版摘要與原文衝突時，以原文為準並修正摘要；無法確認時標示待人工複核。
- 保留正式名稱與必要術語，同一對象不要反覆換稱呼。

## 研究摘要語氣

- 直接從事件、主張或數據切入，避免每篇都以「本文指出」「文章聚焦」「作者認為」開頭。
- 採專業分析口吻，但不要寫成公文、演講稿、教科書或行銷文案。
- 使用台灣常用譯名與金融研究用語，例如「川普」「輝達」「日圓」「紐約」。已有單位慣用譯名時，以單位規範為準。
- 能用動詞就不用抽象名詞；能用短句說清楚就不要疊加轉折詞。
- 保留必要的英文術語，但第一次出現時以自然方式補充中文意思。
- 不刻意口語化，不加入語助詞、第一人稱感想、反問或戲劇化金句。

## 欄位邊界

### `summaryZh`

交代文章處理的問題、主要判斷與重要證據。避免按原文順序逐段翻譯，也不要在結尾硬做願景式總結。

### `keyPointsZh`

每篇依內容使用三至五點，每點只放一個可核對的論點。每一點都要能脫離其他段落獨立理解，開頭直接交代主詞、事件或判斷；不要用「原因與風險」「其他變化」「文章同時指出」等依賴前文的標籤，也不要以短標題加冒號塞入多件事。

### `researchLensZh`

說明研究員回原文時值得檢查的假設、資料、傳導機制或政策取捨。不要寫「值得深入閱讀」「可供參考」等空泛建議。

### `keywordsZh`

使用文章實際涉及的政策、機構、變數或市場名詞。不要放「趨勢」「影響」「挑戰」等無法單獨檢索的抽象詞。

## 格式規則

- 保留既有 JSON key、陣列數量、Markdown 結構、連結與必要標記。
- 不改寫英文標題、檔名、URL、程式碼、指令與資料欄位名稱。
- 若任務指定字數，以任務規格優先；未指定時依研究摘要 reference 的建議長度。

## 完稿檢查

- 開頭是否直接進入具體事件或判斷？
- 是否連續使用「文章指出／作者認為／本文聚焦」？
- 是否有「不只是 X，而是 Y」、三段排比、抽象拔高或昇華式結尾？
- 三至五個重點是否各自提供不同資訊，而且單獨閱讀仍看得懂？
- 研究角度是否指出具體假設、資料或政策機制？
- 人物、數字、日期、因果關係與不確定程度是否忠於英文原文？
- 台灣讀者是否會自然地使用這些詞與句型？
- 讀出聲音是否像研究員寫給同事，而不是模型寫給所有人？
