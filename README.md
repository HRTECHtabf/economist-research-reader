# 《經濟學人》中文研究摘要

以《經濟學人》文章索引與繁體中文研究摘要，協助研究員快速判斷值得深入閱讀的內容。

網站：<https://hrtechtabf.github.io/economist-research-reader/>

完整的專案架構、資料流程、標籤政策、品質檢查與正式提示詞，整理於 [`PROJECT_ARCHITECTURE_AND_PROMPTS.md`](PROJECT_ARCHITECTURE_AND_PROMPTS.md)。

## 目前版本

- 內容每週一期，網站會在週五下午至深夜偵測更新。
- 目前收錄 4 期、共 302 篇文章，最新為 2026-08-15 期；每篇都有繁中摘要、依內容整理的 3–5 點論述重點、研究閱讀角度、繁中全文與英文全文。
- 文章卡可切換「中文導讀／中文全文／英文全文」，並可選取任一中英文段落加入私人筆記；筆記段落會保留底色並可從卡片左側回跳。
- 網站以六個研究主題整合原刊欄目，提供中英文全文搜尋、主題篩選、日期排序，以及可複選的廣義標籤。多標籤採聯集搜尋，命中標籤較多的文章優先顯示；使用者也可保存自己的搜尋標籤。
- 獨立的「趨勢儀表板」可直接依期數切換，並標示各期文章實際刊登日期範圍；所有 NPMI 關聯、tag 次數與中心放射式關鍵字雲都會隨期數重算。未選 tag 時呈現全站最強關聯，也可選一至兩個 tag 分析共同延伸；頁面上方直接列出完整 56 個 tag，底部另提供單一 tag 的跨期占比圖。
- 文章索引右上角提供七步驟功能導覽，逐一說明搜尋、標籤、篩選、閱讀模式與私人筆記。
- 新一期完成處理後會加入既有文章資料庫，不覆蓋先前期數。
- 研究導讀採「事實初稿 → Humanizer 自然化校修」兩階段產生；中文全文採「逐段完整翻譯 → 對照英文定稿」兩階段產生。兩者都會自動擋下被截斷、篇幅異常、非台灣用語及格式失效的輸出。
- GitHub Actions 於週五下午至深夜多次偵測新期，週六上午再補查；同一期不會重複呼叫 Azure。
- 另一支唯讀看門狗每天 12:47 比對上游、GitHub 資料、繁中全文覆蓋率與公開網站；任一環節不同步就留下明確的失敗紀錄，並顯示在維護頁，不會覆寫既有網站資料。
- 公開網站不包含 Azure OpenAI 金鑰；英文全文依本站授權範圍提供站內閱讀。
- 維護狀態頁位於網站的 `/admin/`，可查看內容覆蓋率、最新一期、排程規則及最近的 GitHub Actions 成敗；敏感設定不會送到瀏覽器。
- 收藏、筆記與自訂標籤目前先保存在本機瀏覽器；`supabase/migrations/` 已備妥帳號隔離、跨裝置同步、裝置紀錄及維護資料表，待提供 Supabase 專案公開連線資訊後啟用。

網站檔案位於 `docs/`，可直接由 GitHub Pages 發布。

## 每週更新由誰執行

不需要另外架設常駐 Agent 或讓個人電腦一直開著。GitHub Actions 會在 GitHub 的主機上，依 `.github/workflows/weekly-update.yml` 自動觸發：

- 台北時間週五 13:17、15:17、17:17、19:17、21:17、23:17，以及週六 01:17 檢查新一期。
- 台北時間週六 11:17 再補查一次。
- 每次先比較來源庫最新的 `te_YYYY.MM.DD` 與網站目前期數；相同就安全結束，不呼叫 Azure OpenAI。
- 每篇文章會保存原文內容指紋。只有新文章或原文內容真的改變時才呼叫 Azure OpenAI；未變動文章直接沿用已保存的導讀與全文。
- 新一期出現時，只處理該期新文章一次，不會重跑歷史期數。同一期若後來只新增或修改少數文章，也只處理那些文章。
- 導讀與英文原文保存到 `docs/data/articles.json`；中文全文依文章保存到 `docs/data/fulltext/{issue}/{id}.json`，網站切換閱讀模式時才載入，避免首頁一次下載全庫。這些版本控制檔案就是網站的持久資料庫，瀏覽器不會即時呼叫模型。
- 導讀、全文翻譯與中文定稿都會在處理途中逐批建立檢查點，並由 GitHub Actions cache 保存；若某次執行中途失敗，下次會從未完成處接續，而不是整期重跑。
- 全期處理完成後還會核對全文段落、原文指紋與 manifest 覆蓋率；全部通過才提交網站更新，中途失敗時既有公開網站不變。
- 也可在 GitHub 的 Actions 頁面手動執行 `Weekly Economist update`，作為排程延遲時的備援。
- 更新 Azure Secrets 後，可手動執行工作流程並勾選 `test_azure`；它只測試連線，不會重跑既有摘要。
- `AZURE_OPENAI_ENDPOINT` 同時接受資源根網址與 Foundry 完整的 `/openai/v1/responses` 網址。

公開儲存庫若連續 60 天沒有任何活動，GitHub 可能自動停用排程；屆時到 Actions 頁面重新啟用即可。

## 文章日期來源

EPUB 的日期欄位可能把同一期文章全部標成同一天。網站改以每篇 Economist 原文網址中的 `/YYYY/MM/DD/` 作為文章發布日期，EPUB 日期只在網址沒有日期時備援使用。

## 中英文全文與品質檢查

每篇文章都可在卡片內切換中英文全文，英文內容也納入站內搜尋；文章卡仍保留原刊連結，方便回到來源頁核對。英文全文與繁中摘要保存在 `docs/data/articles.json`，中文全文則按篇存放並延遲載入。

歷史回補可執行 `node scripts/backfill-recent-issues.mjs --start=2026.06.13 --issues=3`。工具會沿用資料庫與檢查點中已完成的摘要，只處理缺少或原文有異動的文章，最後再把網站頂層狀態恢復到來源庫最新一期。

如需重做既有資料的中文導讀，可執行 `node scripts/rehumanize-all-articles.mjs`；流程會逐篇保存檢查點，所有文章通過後才更新資料庫。完成後以 `node scripts/audit-humanized-content.mjs` 檢查全庫的點數、篇幅、完整句、台灣用語與公式化句型。

文章預設標籤必須從 `scripts/general-keyword-taxonomy.mjs` 的固定廣義詞彙表選取，避免把人物、機構全名或單一事件當成預設標籤。如需依目前詞彙表重整全庫標籤，可執行 `node scripts/retag-general-keywords.mjs`；工具會保留摘要與全文，只更新 `keywordsZh`，並以檢查點避免中斷後重跑已完成文章。

如需補做缺少或原文已異動的中文全文，可執行 `node scripts/translate-fulltext-zh.mjs --workers=5`；流程會先完整翻譯，再對照英文做繁中定稿。單篇文章若在主批次未通過，會於同次工作中自動補跑兩輪，每輪只處理仍失敗的文章；仍未通過時才安全中止，且不發布半成品。完成後以 `node scripts/audit-fulltext-zh.mjs` 檢查全文版本、原文指紋、段落對應、數字、台灣用語與異常語句，並更新公開的全文覆蓋率清單。
